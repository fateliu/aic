# 漫想工坊原型方案

从原“校园活动宣传”场景扩展到通用文字与视觉创作。v0.2 验证提示词细化、Skill 引导、分格分镜和人工确认，保留旧项目兼容。不承诺当前已经实现图片或视频生成。

## 创作流程

用户选择文字、图片、漫画或动画，填写想法、风格和画幅，并选择最多三个适用 Skill。资料与 Skill 内容快照保存到项目后，主流程委派提示词子 Agent。

子 Agent 在独立上下文中输出优化提示词、固定角色特征、限制条件、补充建议和问题。用户检查或修改后，显式选择使用当前提示词。主创 Agent 通过有限工具循环写稿和检查，最后再次交给人审并导出。

两个 Agent 是同一后端中的不同职责、上下文和模型调用，并非两个后台常驻进程。开发过程中没有使用真实账户调用模型；规则模式中的主子阶段均为模板演示。

## 模型和 Skill 边界

DeepSeek 使用服务端密钥。子 Agent 的 JSON 调用最多两次；主 Agent 最多六轮，每轮最多四个工具调用，每阶段总超时两分钟。只允许保存与检查创意，不提供命令行、文件系统或任意网络工具。模型输出不作为可执行代码。

Skill 是应用读取的创作指令包。外部链接只是来源说明，不自动抓取；本地注册表决定允许加载的包。提示词子 Agent 与主创 Agent 都得到同一份 Skill 快照，保证中途修改磁盘文件不会改变已有项目。当前不支持完整 Codex Skill 的 scripts、references 自动展开或第三方工具运行时。

## 状态和失效规则

待优化 → 优化中 → 待确认提示词 → 创作中 → 待确认草稿 → 已确认。失败可重试。项目读写使用单进程锁及原子文件替换；写入草稿、编辑提示词和确认时检查版本。编辑提示词清空下游草稿，编辑作品撤销导出确认。进程中断后的阶段可重新运行，尚未实现断点续作。

## 后续接入媒体生成

现有媒体请求说明包含 version、projectId、revision、kind、ratio、characterAnchor、negativePrompt、units。图片项目一个单元，漫画四个单元，动画三个五秒单元。

真实渲染的下一步是选择提供方并实现适配器，加入报价展示、用户确认、按项目版本和单元编号的幂等键、持久任务编号和轮询。之后再加入角色参考图、素材存储、单格重生成、视频合成和成品下载。不要把 `not_connected` 响应改成假成功来模拟生成。

## 已知限制

- 自动审核只验证结构、长度和单元数量，不保证内容事实正确、角色真正一致或视频可实现。
- 当前角色锚点以文字传递，尚无图片参考约束；画幅和风格是提示词条件，未验证渲染效果。
- 图片、漫画与动画仍停留在提示词和脚本，没有媒体成品。
- `.env` 需要重启生效；背景与 Skill 注册表可刷新生效。已有项目使用原 Skill 快照。
- 背景本机预览仅当前页面有效；永久背景通过 public/theme.json 配置。
- 本地 JSON 存储与进程锁不支持多实例，公网部署前必须补权限、数据隔离与任务队列。

试用优先记录优化前后提示词的可用性、用户修改次数、模型失败率和是否保留原始设定，再决定媒体生成投入。赛事要求与服务价格应在实际提交或采购前另行核实。
