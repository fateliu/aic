# 校园活动创作 Agent 原型方案

第一版验证一个问题：社团负责人提供一次活动资料后，是否能在一个工作台中获得可修改、事实字段一致、能导出的宣传草稿。沿用原讨论稿的校园场景，以人工确认作为创作和导出的分界。

## 本次实现范围

输入六项结构化活动资料。规则模式用于零成本演示；模型模式通过有限工具循环生成创意。模型只能提交创意文案和分镜，不具备文件、命令行、网络检索或付费媒体生成权限。活动事实单独保存，由程序放入文案和海报。

模型可选择 `save_creative` 提交草稿，收到长度或结构错误后修正，再使用 `review_creative` 检查。工具检查通过后，程序停止循环并交给人审；人审通过后导出。使用固定工具边界，便于理解和测试，不引入多 Agent 协作。

状态流：待生成 → 生成中 → 待确认 → 已确认。生成失败时显示失败原因并可重试。修改或重生成会使确认失效。项目版本号防止一个窗口误确认另一个窗口修改过的内容。

## 当前限制

- 模型检查是结构与长度校验，事实语义、措辞和素材授权由人检查。即使事实单独保存，模型仍可能在正文中编造信息。
- 规则模式的风格影响分镜提示，海报只有一种程序排版，不代表完整风格控制。
- 海报为可伸长 SVG，优先保证信息完整，尚无固定平台尺寸、图片背景、二维码或字体嵌入。
- 两个分镜只是 10 秒视频的计划，不包含模型视频、配音、音乐和 FFmpeg 合成。
- 本地 JSON 适用于单机原型。进程中断后可以重新生成，未实现持久任务队列或断点续作。
- 真实 Ollama 服务未联调，工具兼容性、输出质量和性能仍待选择模型后验证。

## 下一步开发顺序

| 次序 | 功能 | 验收条件 |
| --- | --- | --- |
| 1 | 选定一个真实文字模型 | 用 5 个活动样例完成工具调用、修正和人审，记录失败原因 |
| 2 | 图片背景生成 | 真实生成图片并保存模型来源；活动文字由程序叠加，导出固定尺寸 PNG |
| 3 | 视频任务与预算确认 | 分镜确认后才提交生成；展示可核对的报价、任务编号、状态和失败原因；有幂等保护 |
| 4 | 视频合成与导出 | 将真实生成片段与字幕合成 MP4，明确素材来源与授权 |
| 5 | 多人使用和参赛演示 | 再迁移到正式前后端、数据库、对象存储、登录和在线部署 |

## 试用方式

先邀请 3 位社团成员，分别输入一个真实活动。记录首次可用草稿耗时、人工修改次数、事实错误数、模型失败次数，以及是否愿意再次使用。规则模式与真实模型的结果必须分开记录，不能把模板表现当成模型成绩。

建议演示顺序：填写资料，生成草稿，查看工具记录，修改一句文案，确认版本，下载海报与文案，重新打开项目检查保存结果。真实视频尚未接入时只展示分镜，不展示虚构的生成进度。

本方案不确认原文稿中的赛事日期、资格或模型价格；提交作品和采购服务之前，需按官方最新信息另行核实。
